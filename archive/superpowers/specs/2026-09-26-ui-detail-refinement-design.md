# 前端 UI 细节重构设计规格

## 背景

项目已经具备黑白极简基线、透明内容层和水墨背景机制。本次工作聚焦四类前端界面的信息层级、视觉细节、响应式编排和状态过渡，不重新设计后端，不改变背景机制，不改变选课业务状态机。

本规格基于已确认的决策：

- 覆盖登录、学生看板、选课大厅、管理员后台。
- 学生看板与选课大厅继续分开。
- 学生看板开放前突出开放时间，开放后转向报名进度。
- 课程信息保持均衡紧凑，桌面端便于比较，手机端允许按任务重新编排。
- 全站黑白极简、克制透明；管理后台保持运营工作台密度。
- 动效采用克制而有触感的状态过渡，不增加持续装饰动画。
- 全程不使用子代理，实施按小模块内联推进。

## 目标

1. 让用户首屏快速理解当前选课窗口状态和目标课程结果。
2. 移除学生界面中的内部实现说明，保留所有能帮助用户判断或采取行动的反馈。
3. 让四类页面共享同一套黑白、透明、发丝边框、焦点和状态层级。
4. 让手机端优先满足查看窗口状态、查看报名结果和完成课程操作的顺序。
5. 在不改变现有业务判定和背景机制的前提下，引入有限的状态过渡细节。

## 非目标

- 不修改水墨背景图片、固定背景层、图片滚动位移、黑色渐变遮罩、`.canvas-bg`、`.canvas-bg-img`、`.canvas-bg-mask` 或 `.app-content` 的机制。
- 不修改后端接口、请求频率、缓存、调度、自动重登、账号隔离、目标保存和报名状态机。
- 不用本地倒计时替换后端 `window_opened` 或 `window_closed` 判定。
- 不用视觉状态覆盖课程平台的 `btn_type`、`can_select`、`title` 规则。
- 不将管理员诊断能力删除或伪装成学生功能。
- 不整套迁移 beUI、Rare UI 或 liquid-glass，不增加无法证明收益的依赖。

## 信息架构

### 登录页

保留账号/学号、密码、密码显隐、登录提交状态、认证错误、激活码模态框和退出/关闭路径。删除页脚“账号隔离”“实时调度”等实现说明，以及不服务于登录决策的系统宣传标签。加载和错误状态必须仍然可理解，激活入口不能被视觉收敛隐藏。

### 学生看板

看板保持“窗口状态 → 目标课程 → 课程结果”的阅读顺序。

- 开放前：开放状态和倒计时是首要内容，目标课程作为下一层内容。
- 开放后：窗口状态缩为简洁状态提示，目标课程与报名结果成为首要内容；用一次短促的布局/状态过渡完成焦点切换。
- 保留：开放时间、窗口已开放/待命/已关闭、目标课程、成功/失败/满员/提交中等用户可理解状态、可行动的重新登录入口。
- 移除学生可见的：心跳轮询周期、频控保护策略、自动恢复机制术语、教务令牌技术状态、原始调度日志和内部事件流。
- 失败原因只保留能帮助用户行动的短文案；网络异常、凭据失效和课程提交失败必须各自有明确出口。

### 选课大厅

保持选课大厅独立，首屏顺序为窗口状态、批次/目标摘要、搜索与筛选、课程比较区。桌面端维持均衡紧凑网格；手机端把窗口状态、批次切换、搜索和课程操作排列成单列可操作区。

保留批次、搜索、排序、余量过滤、优先级、教师、地点、容量、报名/退选和目标保存反馈。课程 ID 和内部技术字段降为辅助信息，不再抢占课程名、可操作状态和容量信息的视觉注意力。

课程按钮的显示与禁用仍完全服从 `btn_type`、`can_select` 和平台 `title`。动效只能表达已发生的用户操作，不能表达尚未被平台确认的成功。

### 管理后台

保留现有激活码、系统配置、运行状态、账号管理、日志总览五个分区和运营工作台的信息密度。统一黑白透明视觉、状态徽标、表单间距、错误态和危险操作确认，不把诊断信息改造成默认不可见的深层抽屉。可以清理重复解释和宣传性副标题，但运行配置、账号操作、状态指标和日志仍必须可直接查找。

## 视觉系统

### 基础层

沿用现有黑白变量、低透明度面板、冷灰文字、发丝边框、4/6/8px 几何圆角和等宽数字。优先调整公共组件及页面组合方式，不建立第二套颜色或卡片体系。

透明面板必须在水墨背景和 Android WebView 上保持可读。现有 `.glass` 不默认重新启用 `backdrop-filter`；任何滤镜实验必须单独验证移动端，不得作为基础可读性的前提。

### 层级

- 主操作：白底黑字或清晰的白色焦点边界。
- 次操作：透明底、冷灰边框，悬停/聚焦时提升对比。
- 状态：文字、图标和灰阶共同表达，不能只依赖颜色。
- 辅助信息：缩小字号和降低对比，但不把必要错误或按钮提示降到不可读。
- 诊断信息：管理员页保持清楚，学生页不暴露实现术语。

### 动效

只用于按钮按下、批次切换、折叠展开、提交中/成功/失败状态、登录激活模态框和看板开放前后焦点切换。默认使用短时、低位移、低对比过渡；不增加持续漂浮、鼠标追踪、眩光、数字翻牌或全页背景动画。必须支持 `prefers-reduced-motion`，关闭动效后状态与操作仍完整可理解。

## 外部资源策略

- beUI：只筛选与按钮反馈、标签切换、状态反馈直接相关的公开实现；先核对单组件依赖和许可，再决定是否采用。项目已有公共组件优先于新建同类组件。
- Rare UI：只借鉴能提升信息层级或操作反馈的组件；不引入纯展示型装饰。
- Transitions.dev：作为状态过渡和面板切换的参考来源，优先复制必要的 CSS/React 片段，不为目录示例安装整套运行时。
- `samasante/liquid-glass`：仅作为小面积实验候选。不得用于整页、宽导航、倒计时主面板或大量课程卡片。必须提供静态透明降级，并验证 Android WebView、桌面 Chromium、Safari/Firefox 的可读性和帧率表现；验证不通过则不引入。

## 验收标准

### 信息与行为

- 登录页不再显示“账号隔离”“实时调度”等内部机制说明。
- 学生看板不再显示心跳周期、频控策略、教务令牌技术状态和原始调度日志。
- 学生仍能看到开放时间、窗口状态、目标课程、报名结果、必要失败原因和重新登录入口。
- 管理后台五个分区、配置、状态、账号、日志和危险操作确认均可用。
- 选课报名、退选、目标保存、返回、激活和失效会话行为与改造前一致。
- `btn_type`、`can_select`、`window_opened`、`window_closed` 仍是对应状态的唯一业务来源。

### 响应式与视觉

- 桌面端看板开放前突出倒计时，开放后突出报名进度。
- 手机端看板优先显示窗口状态和报名结果；大厅优先显示批次、搜索和课程操作。
- 四类页面共享黑白极简、透明面板和发丝边框语言，管理员页保留较高信息密度。
- 背景图、遮罩、滚动位移和内容层级机制无变化。
- Android WebView 不出现由新增滤镜或透明效果引起的黑块；无玻璃实验也能正常使用。
- 开启减少动态效果后，所有状态、反馈和操作仍可辨认。

## 验证方式

- `cd web && npm run build`
- `cd web && npm run guard`
- `cd web && npm test`
- 启动前端开发服务，分别以桌面和窄屏检查登录、看板开放前/后、选课筛选与操作、管理员五个 Tab。
- 实际检查 Android WebView 或对应移动端发布壳中的透明层、弹窗、滚动和按钮可读性。
- 仅在新增纯函数或可观察行为边界时添加 Vitest；不为 JSX 文本复制或静态类名堆测试。
